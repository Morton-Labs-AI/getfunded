# Handoff, 2026-10-08: data quality work and the first Open Foundation List release

This note records where the corpus work stood at the end of the 2026-10-08 session, what still has to
run, in which order, and which decisions are open. It is written for the maintainer who runs the hosted
corpus. Account details, connection strings and machine paths are not in this repository; they live in
the operator's private notes.

## 1. What was asked

Three ways to make the database more accurate and to add facts that are not on a 990-PF, and a way to
publish the 990-PF foundation data as an open, downloadable list.

## 2. What was built (all on `main`)

| Idea | What it does | Code | Live? |
| --- | --- | --- | --- |
| 1. Filers as witnesses | When several charities' own returns (Schedule I) write a recipient name together with its EIN, that name becomes an alias for the organisation. Unlinked foundation grant rows with the same name and state are linked to it. | migrations 0027, 0034; `funderdb resolve aliases --build / --report / --sample / --apply / --unapply` | live (910,656 rows linked) |
| 2. IRS standing | Loads the IRS Automatic Revocation list and Publication 78, so a profile can say whether the IRS still recognises the organisation as exempt, and whether it kept filing after a revocation. | migrations 0028, 0032; `funderdb ingest irs-standing` | live |
| 3. Open-door test | Reads how a foundation answered the application question on each earlier return, and counts how many of a year's recipients it had not funded before. | migration 0029; `funderdb derive turnover` | live (run of 2026-10-09: 159,831 rows for FY2023 to FY2025) |
| Address from the latest return | City, state and zip from the newest return for organisations the IRS master file does not list. Never the street. | migrations 0030, 0031; `funderdb derive org-address` | live (52,714 organisations) |
| Qualifying distributions repair | Fills a value the parser missed on returns filed before 2021. | `funderdb repair qualifying-distributions` | live (118,757 filled; 8,945 returns state no amount) |
| Backfill 2017 to 2020 | Loads the IRS index years 2017 to 2020, one zip file at a time, with the next file downloaded ahead. | `funderdb backfill --discard-zips --prefetch N` | live (36 zip files) |
| Open Foundation List | Writes `foundations.csv.gz`, `foundation_years.csv.gz` and one `foundation_grants_<fy>.csv.gz` per fiscal year (organisation-linked grants only) with a manifest. The website page `/foundations` reads `apps/web/content/data-release.json`. | `funderdb export foundations` | live: GitHub Release `data-2026-10-08`, published 2026-10-09 |

## 5. Open decisions for the steward

- **Tier 3 recipient matches.** `resolve recipients --max-tier 3` would link 1,290,069 more foundation
  grant rows ($42.3 billion) and 20,602 Schedule I rows. On keys like the strict alias class, tier 3
  agrees with what filers wrote 99.54% of the time. Not applied. Decide after a sample audit like the
  alias one.
- **The word OTHERS as a recipient name.** The placeholder rule (migration 0034) treats "ALL OTHERS" as
  a placeholder but a bare "OTHERS" as a name. Decide whether bare "OTHERS" should also be a
  placeholder.
- **Human check of the alias audit.** The 300 labels came from model agents. A person should read a
  sample before the 98.7% figure is quoted anywhere as a precision number.
