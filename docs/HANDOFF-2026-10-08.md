# Handoff, 2026-10-08: data quality work and the first Open Foundation List release

This note records where the corpus work stood at the end of the 2026-10-08 session, what still has to
run, in which order, and which decisions are open. It is written for the maintainer who runs the hosted
corpus. Account details, connection strings and machine paths are not in this repository; they live in
the operator's private notes.

## 1. What was asked

Three ways to make the database more accurate and to add facts that are not on a 990-PF, and a way to
publish the 990-PF foundation data as an open, downloadable list.

## 4. Run order for the next session

Run from `corpus/` with the owner connection loaded into the environment (see the private notes),
the machine kept awake, and `PYTHONUNBUFFERED=1`. Never print the connection string.

1. **Finish the alias apply.** Check `select count(*) from internal.recipient_alias_links;`. It should
   be close to 910,656. If the apply stopped early, run
   `uv run funderdb resolve aliases --apply --min-filers 3` again. It resumes. Then run
   `uv run funderdb resolve aliases --report` and paste the dated report block at the end of
   `corpus/benchmarks/queries.sql`.
2. **Turnover.** `uv run funderdb derive turnover --fy 2023 --fy 2024 --fy 2025` takes about one hour.
   Slice 117 alone takes about 3 minutes and sets one foundation-year aside, which is expected. Then
   `uv run funderdb derive turnover --report`. Capture output with `tee`, not `head`.
3. **Refresh views.** `uv run funderdb refresh-views` takes about 13 minutes. Never run it while an
   export is running.
4. **Embeddings.** `uv run funderdb embed sync --kind foundation --dry-run`, read the count (about
   17,000 documents changed state), then run it without `--dry-run`. This spends Voyage credit.
5. **Export rehearsal.** `uv run funderdb export foundations --timed-dry-run`. Checks F1 to F8, P1 (no
   amended return counted twice) and P2 (posture view not stale) must all pass.
6. **Real export.** `uv run funderdb export foundations --out data/open-foundation-list --tag data-2026-10-08 --release-json ../apps/web/content/data-release.json`.
7. **Publish.** `gh release create data-2026-10-08` with the csv.gz files, the manifest, the README and
   the LICENSE from the output folder.
8. **Website.** Commit `apps/web/content/data-release.json`, push, deploy production from `apps/web`,
   open `/foundations` and check that the release shows.

## 5. Open decisions for the steward

- **Tier 3 recipient matches.** `resolve recipients --max-tier 3` would link 1,290,069 more foundation
  grant rows ($42.3 billion) and 20,602 Schedule I rows. On keys like the strict alias class, tier 3
  agrees with what filers wrote 99.54% of the time. Not applied. Decide after a sample audit like the
  alias one.
- **The word OTHERS as a recipient name.** The placeholder rule (migration 0034) treats "ALL OTHERS" as
  a placeholder but a bare "OTHERS" as a name. Decide whether bare "OTHERS" should also be a
  placeholder.
- **Human check of the alias audit.** The 300 labels came from model agents. A person should read a
  sample before the 98.7% figure is quoted anywhere as a precision number.
